A meter in every section, not one borrowed via chips

Companion to METER_V2_2026-08-04.html — that mockup never showed this page against real, multi-candidate production data. This one does, and the shipped design (built correctly, in #315, per that spec) turned out to misrepresent whose meter a reader is looking at. This explores the alternative: every candidate's own section carries its own static meter.

What the live preview found

Not a rendering bug — the spec itself. A reader who clicks a trailing candidate's chip sees that candidate's share highlighted inside a different candidate's card, because there is only one meter and it lives in the leader's header.

Shipped, then unmerged (#315)

One shared meter, in the leading candidate's own header. Every candidate's chip sits there too — including candidates who have their own section below with nothing in it.

The header says whose meter this is. The chips say otherwise.

Proposed (#325, this page)

Every candidate's section carries its own meter, always in that candidate's own context. No click, no borrowed state, no section that promises a meter it doesn't have.

What a section shows is what it's about.

Same race, both models

Seattle City Council, District 5 — a real four-candidate race, real production data. Nilu Jenks's chips carry Julie Kang's, Silas James's, and Dimitri Georgakopoulos's context too, even though their own sections, right below, show nothing.

The proposed model against harder cases

A clean, decisive majority, and — real production data, not a synthetic stand-in this time — an exact tie with the heaviest co-endorsement splitting of any 2026 race. The four-candidate field above already stress-tests "does this get repetitive"; this pair stress-tests the palette and split-half treatment instead.

Decided

Decided in review of the first draft, 2026-08-05 — this page is now the canonical reference for #325's implementation, the same role METER_V2_2026-08-04.html played for #312–#316. The formal decision-log entries land in docs/METER_V2.md when #325 itself ships, matching how #314's and #315's own decisions were recorded.

  • Chrome and sizing. Full section width, but the meter itself stays a fixed track (16rem here, left-adjusted) — every row's bar occupies the same physical width for scannability, the same job the card-width headline meter did. The freed space at full width goes to the label, right-adjusted.
  • Zero-endorsement candidates. No section, in either model. This page is about who should be voted for, not who can be — every real race below (seattle-city-council-5, seattle-municipal-court-judge-5, supreme-court-justice-3) has exactly one such candidate on the ballot, and neither model shows or explains them.
  • Resting label. Retained, but outside the meter, in the flexible label — a percentage that would need to fit inside a half-endorsement sliver of highlighted bar doesn't fit there. Count stays the caption's lead (METER_V2.md Decision #6); percentage now rides beside it.
  • The headline meter's own fate. The race itself gets no meter on this page at all — every candidate gets one, colorized for that candidate, same width and block layout throughout. A race-level meter remains the guide/ballot overview's job, untouched by this proposal.
  • Comparisons and social cards — recommendation, not yet confirmed. No change. Both already draw the single plain resting-state meter for a race, never in candidate context; this proposal only touches the race-detail page's per-candidate sections.
